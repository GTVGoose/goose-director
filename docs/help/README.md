# Nexus Help — support docs for new users

This folder is the beginner support set. It's written for someone who is **new to AI agents,
harnesses, and GitHub** and wants to actually set Nexus up and grow with it — not a reference for
experts. T27 surfaces this content in an in-app **Help** view; it also stands alone as Markdown.

**Hard rule for everything in here:** this is **generic user enablement**. It
teaches Nexus and general concepts only. It must **never** describe, name, or leak any specific private
system, vault, agent, or workflow we run internally. Give newcomers a roadmap they can build their own
thing with — not our recipe.

## Contents

- **[Getting started roadmap](getting-started-roadmap.md)** — the path from install to a working
  system, in plain steps. Start here.
- **[UI glossary](ui-glossary.md)** — every term you'll see in the Nexus interface (Brain, Council,
  vault, canon, sandbox, capabilities, cost meter…).
- **[Agentic-systems glossary](agentic-glossary.md)** — the concepts behind AI agents (agent, model,
  prompt, context, memory, tools, MCP, orchestration…). No prior background assumed.
- **[GitHub & Git glossary](github-glossary.md)** — repos, commits, branches, pull requests, and why
  version control makes agent work safe. For people who've never used Git.

## How this maps to the product

- The **first-run tutorial** (the onboarding flow) is the *guided* version of the roadmap — it walks
  you through the same ideas the first time you launch. This folder is the *reference* you return to.
- Help is reachable from the sidebar at any time; you don't have to remember anything from onboarding.
- Terms are cross-linked: a UI term like "Council" links to the agentic concept it's built on.

## Writing style (for contributors)

- Define every term in one plain sentence before using it.
- Prefer "a folder whose history is tracked" over "a VCS working tree."
- One idea per entry. Link, don't repeat.
- No internal project names, no secrets, no "how we do it" — only "how you can do it."
